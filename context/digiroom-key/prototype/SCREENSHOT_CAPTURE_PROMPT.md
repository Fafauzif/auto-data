## Capture specification

- **Desktop:** Capture every distinct view in PNG at a 1920 × 1080 CSS viewport. Use a slide-ready viewport shot for important screens. Where the action or supporting evidence sits below the fold, add a separate full-page companion or a clearly named detail frame. For a scrollable dialog, capture its meaningful lower content as a companion.
- **Mobile:** Capture key customer steps at 390 × 844 CSS pixels with touch emulation and device scale factor 2. Include Home, 3D or 2D garage and family views, the visit card and drive request, customer drive status and buyer quote, Bandung access map and service offer, authorized payer approval, receipt, inspection request, upgrade acceptance, and the resulting vehicle record. Add a mobile shot when a key action has a materially different presentation.
- Use the app content only. Keep native UI if it is genuinely capturable. Wait for fonts, images, 3D or fallback, map state, and status text to settle, then position the screen so the primary action and outcome are visible. Move the mouse off controls unless an actual tooltip is the subject. Confirm every screenshot visually. Keep original brand styling and preserve map attribution. Verify that all captured content fits its viewport and that any full-page image contains the full intended section.
- Prefer a consistent local atlas for paired map evidence if live tiles are unreliable. Identify the map source in the caption. The four-market counts are modeled origin points and must be described as such. Keep quote and service values labeled as sample demo outcomes where needed.
- Use share and payment previews within the app. Do not send messages, submit real requests, access real customer data, or use production credentials. If a state cannot be made visible or a native chooser cannot be captured, record it in the coverage notes with the reason and the closest verified screen.
