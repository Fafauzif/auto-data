# Candidate directions for user selection


These 25 distinct cards are hypothesis-led options grounded in public competitor mechanisms. They do not establish an unmet Auto2000 need, adoption, impact or novelty. Each card must be linked to Auto2000 evidence and contrary cases before user assessment. No winner, implementation or roadmap is supplied. Counts refer to analytical options, not empirical observations.


## OPT-C01: Explain the distinct roles of ecosystem apps

Evidence: COMP-001, COMP-002, COMP-007. Class: information and role clarity.

Mechanism: Clarify which existing route owns a customer task and what information it can reliably show.

Benefit hypothesis: Reduce choosing the wrong route or repeating a search.

Rival: Users already understand the roles; low activity reflects infrequent need.

Existing analogue: mToyota advertises ownership and purchase functions; SEVA supplies finance routes.

Transfer limit: Value would be role clarity, not a new version of an existing feature; app integration remains unknown.

Stakeholder trade-off: Central consistency versus dealer-specific propositions.

Economic link: Only useful if more eligible opportunities are retained or realizable servicing effort falls. Costs remain unknown.

Kill condition: Current users find the right existing route without consequential uncertainty.
