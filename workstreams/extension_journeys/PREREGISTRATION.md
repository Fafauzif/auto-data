# Targeted second-round journey falsification

Eight checks were registered before new page interactions. The purpose is to distinguish task-specific information access and confirmation boundaries from universal absence claims. No customer failure rate, causal business effect or performance benchmark will be estimated. Mobile is a capability check and will not be represented as mobile testing if unsupported.

**XT01: Viewport feasibility.** Does the advertised browser API support device/viewport control? Counterexample criterion: A real mobile viewport can be set and verified; otherwise explicitly not tested.

**XT02: BEV finance access.** Is finance preview universally blocked until contact, or does access vary for a BEV product? Counterexample criterion: A selected bZ4X scenario produces pre-contact illustration with explicit assumptions.

**XT03: BEV versus hybrid workshop qualification.** Does workshop selection support the BEV model before the identifier boundary? Counterexample criterion: bZ4X and hybrid selections can be compared without plate or personal details; no downstream capability inference.

**XT04: Model-specific T-Care guidance.** Are the prior hybrid free-service terms universal across BEV and conventional models? Counterexample criterion: Different supported model/variant rows or programme conditions demonstrate job-specific access and limits.

**XT05: BEV battery and warranty information.** Can a customer find model-specific battery/warranty terms before contact? Counterexample criterion: An actual public product journey exposes a bounded warranty/maintenance statement, with source date and scope.

**XT06: BEV test-drive versus confirmed appointment.** Does BEV test-drive availability or confirmation differ from the observed hybrid route? Counterexample criterion: Accessible bZ4X route and model/branch/FAQ conditions are recorded; no appointment submitted.

**XT07: HHC alternate-language discovery.** Does one more plausible Indonesian search phrase falsify the apparent English-query discovery gap? Counterexample criterion: A programme/eligibility result is discoverable through the site search; a null local result is not sitewide absence.

**XT08: Branch job information.** Does a named branch page expose model/job capability beyond the coarse category filter? Counterexample criterion: A named branch explicitly supports a defined EV service job or links to scope details; hours alone are not capacity proof.
