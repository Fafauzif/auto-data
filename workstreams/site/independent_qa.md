# Independent cached-source QA of site extraction

Review date: 11 November 2026. Reviewer: a separate AI research agent. This was not human annotation, a browser render, participant usability testing or an independent sample of customers. No network request was made for this QA. The reviewer read the collector, queried the active SQLite database read-only, and compared 24 deliberately selected successful cached responses across all 15 then-observed template families. Exact URLs, request IDs, body hashes, comparisons and selection are in `qa_records.csv`; cache provenance uses the shared transport database. The crawl continued during review, so `qa_snapshot.json` is a time-specific snapshot rather than the final denominator.

The selection covers an adviser promotion, catalogue, national editorial, local branch, ten product/template types and service/utility pages, plus additional purchase/ownership/editorial tasks. It is purposeful template coverage, not a probability sample or evidence of site-wide prevalence.

## Main conclusion

The collector's stored values were reproducible from cached HTML, but the v1 “main” text and main-link labels do not yet isolate the substantive content reliably. Two observed extraction defects can change downstream content/intent interpretation: navigation remains in text, and promotion modules can trigger numeric-cost flags for an unrelated article. Phone-number paths also survive link sanitization and need removal or categorization in public exports. These are research-pipeline findings, not defects attributed to Auto2000's customer experience.

## Amount handling

The `amounts.scope` label correctly says raw-main-text amount, not a verified offer. Preserve that limitation. Current extraction does not reconcile model/year/variant/location, validity, tax, down payment, first installment, fees, eligibility or stock. Several amounts in one page can describe different products or promotion modules. They are mentions, not separate quotes, transactions or opportunities.

No decimal-form currency match was observed in the 24-page sample. Code inspection nevertheless finds a potential normalization risk: it removes every nondigit, so a decimal notation such as Rp1.000,50 would become100050rather than1000.50. This is a code-level counterexample, not an observed price error on the website. Price ranges, juta/miliar suffixes and embedded variant context are also outside the current numeric parser. Do not build a price-comparison result from these mentions without a separate entity/offer reconciliation process.

## Reproducibility and privacy boundaries

The independent review read source HTML from successful private cached bodies using the collector's request ID and transport cache key. It did not modify `site_evidence.sqlite`, its rows, the collector or the root export logic. The QA script uses the same available HTML parser but checks specific source/container facts independently; zero value mismatches therefore supports reproducibility, not independent measurement validity.

Current URL sanitization removes query/fragment information, which appropriately avoids many contact/session parameters but also removes task context. A sanitized target cannot establish that the live original link failed to preserve product/branch context. Exact cache contents remain available privately for bounded reinspection. Adviser source URLs can contain public-role identifiers; public exports should avoid unnecessary personal contact fields.

Main content hashes and simhash remain derived representations. Similar reusable templates can inflate similarity; different incidental modules can reduce it. The absence of exact hash duplicates in a purposive sample does not establish unique editorial information site-wide. Topic flags refer to the selected extraction boundary only.

## Status of remediation

The root agent was notified of QA-F01–F04 while its collector was active and stated it would correct extraction and reparse all successful cached responses. This document describes the reviewed v1 behavior. It does not claim a correction has already passed. After reparsing, repeat the same fixed 24-source check and compare the final export, rather than presenting old QA values as approval of new outputs.
