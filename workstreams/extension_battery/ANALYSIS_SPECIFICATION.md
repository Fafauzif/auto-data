# Bounded battery telemetry analysis specification

Written after reading the dataset catalogue and README, before loading numerical MAT signals. This is an auxiliary methods stress test, not Auto2000 evidence or a validated state-of-health estimator.

Source: Pozzato and colleagues, *Real-world electric vehicle data: driving and charging*, Mendeley Data V2, DOI 10.17632/7vdkzpnjgj.2, CC BY-NC 3.0. The README says the public signals have already undergone cardinality reduction. Current, voltage, BMS state of charge and pack temperature each have their own time axis. Charging current is negative; driving current is positive for discharge and negative for braking. Published absolute epoch time is present. No GPS or owner fields are listed in the catalogue; actual MAT variable names will be inspected before raw staging.

The bounded initial selection is Charge Folder1 and Folder7, and Drive Folder2, Folder8 and Folder16. These cover early, middle and later source-folder positions and both operating modes without downloading the entire repository. They are not a random sample and folder number is not assumed to be a month. Folder15 is initially omitted because its 171 MB size exceeds the initial per-file bound. Selected raw bytes total about 283 MB. Keep missing/download-failed files explicit.

1. Audit actual variable names, signal lengths, finite values, monotone timestamps, duplicate/reset times and sampling intervals. Count scalar signal observations separately from timestamp scalars, files, events and vehicles. Do not pad a common grid and call it new measured data.
2. Test whether rowwise joining would be legitimate: compare lengths and corresponding timestamps for current/voltage/SOC/temperature. Time-align only within observed overlapping support and document interpolation. No extrapolation. Report both zero-order hold and linear voltage alignment as sensitivity if the source permits.
3. Segment disjoint intervals conservatively using observed clock resets and large gaps, after inspecting time units. Integrate current and current×voltage only over intervals whose time coverage is supported. Report gap-threshold sensitivities rather than integrating across unobserved hours. Cardinality-reduced spacing is not automatically sensor loss. These are observed terminal intervals, not wall energy, charger efficiency, total-trip consumption or battery usable capacity.
4. Describe SOC windows and temperature heterogeneity. If sufficiently supported charging intervals exist, report observed Ah per reported SOC percentage point as a descriptive signal-consistency diagnostic. Do not multiply it into claimed capacity or state of health. Test whether one universal interval slope is compatible with the observed selected sessions, while considering temperature, rate, endpoints, quantization and sampling. A varying slope does not by itself prove degradation or a BMS error.
5. Assess what is not identified: no health reference test, known beginning-of-life capacity, Toyota calibration, Indonesian population, certification standard, causal battery-failure outcome or residual-value label is assumed. State-of-charge percentages are not state of health. A telemetry pipeline can be feasible without any validated health guarantee.

Release exact licensed raw files only after checking actual keys for GPS, VIN/owner/contact fields and documenting absolute-time metadata. Never claim a complete privacy certification from a field-name check. Preserve original file hashes and source download URLs. Public figures will use elapsed or relative time, not a driver's precise date/time trajectory.
